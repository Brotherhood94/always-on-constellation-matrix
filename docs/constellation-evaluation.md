## Recommended sequence

### 1. Establish the Matrix and ACP regression baseline

Run the [four prepared Matrix scenarios](acceptance.md#chief-of-staff-collaboration-scenarios) and record the outcomes before changing the Instance or connector. Use Lab fixtures for a controlled local trial of session restoration, cancellation, permission behavior, and delivered artifacts. Capture fixed scenario inputs, engine settings, delivery receipts, and independent expectations. The Lab's `validate` step makes no connections. A real `run` sends prompts through ACP and creates private reports. The existing Matrix scenario suite remains the delivery, encryption, mentions, handoffs, and recovery check. The upstream import example covers Slack recordings. Publish only sanitized measurements if sharing evidence. [Agent Experiment Lab](https://github.com/microsoft/amplifier-acp-lab/blob/6f40f511f2d6b2a0e53e561656ec2bb49c4d9fba/README.md) · [Bindings, repeats, and evidence](https://github.com/microsoft/amplifier-acp-lab/blob/6f40f511f2d6b2a0e53e561656ec2bb49c4d9fba/docs/execution-reference.md)

**Acceptance.** Run one deterministic fixture twice and compare its delivered output and result independently. Demonstrate that uncertain completion is reported without replaying work. Compare the ACP results with their separately collected Matrix equivalents.

### 2. Verify Instance lifecycle and recovery

Record the External Worker's installed Instance and engine, release digests, Instance ID, home, workspace, and advertised ACP session capabilities in private operator notes. Verify that the live connector uses the Instance's supported `acp` attachment path. The attach command targets the existing identity and relays the engine's negotiated session capabilities. Constellation Runtime's `sessions` and `events` commands belong to that Runtime and require a separate compatibility check if evaluated against an Amplifier-backed deployment. [Instance ACP boundary](https://github.com/microsoft/amplifier-constellation-instance/blob/693cf06d9d0322efa6a5626cff24cbba517eb9fc/docs/acp-boundary.md) · [Runtime inspection](https://github.com/microsoft/amplifier-constellation-runtime/blob/74a014623db6e375c90657d82b228cc7510e6545/README.md#configure-and-inspect)

Use a stopped-instance checkpoint and encrypted backup for one isolated recovery rehearsal. Include the external connector's Matrix device and encryption state, queue, thread-to-session mapping, and any separate workspace in the recovery plan. The upstream checkpoint has its own integrity manifest, excludes external files, and produces an unencrypted archive. Retain it only within the encrypted backup workflow. Update checks can be useful in advisory mode. A binary update is a separate, operator-requested action after the Matrix connector drains work and ambiguous delivery is reconciled. [Checkpoint format and restore](https://github.com/microsoft/amplifier-constellation-instance/blob/693cf06d9d0322efa6a5626cff24cbba517eb9fc/docs/checkpoints.md) · [Instance update and recovery behavior](https://github.com/microsoft/amplifier-constellation-instance/blob/693cf06d9d0322efa6a5626cff24cbba517eb9fc/docs/updates.md)

**Acceptance.** Verify instance identity and model access with a synthetic task, resume an existing Matrix thread after restart without a duplicate reply, and inspect an isolated restored copy with delivery stopped. Test rollback before the first production updater cutover. Keep the original Matrix device exclusive throughout.

### 3. Pilot one reviewed native persona

Let the Chief of Staff evaluate the Matrix baseline. Select an observation that supports a narrow change to the External Worker's working style or communication. Use synthetic prompts to compare the draft with the unprofiled baseline. Workshop supports blind comparison with a configured evaluation endpoint. Score both responses against the same criteria before revealing the profile. After operator review, import that worker's own `twin-profile/1` package through its Instance, using the installed profile revision and recording the source version and digests. Instance stores the communication and working-style documents together, supports restoring a previous pair, and records evidence that an effective profile reached the backend. The profile can influence model choices within the permissions already set by the installation. Preserve the existing Codex ACP workers and their policy. [Matrix scenarios](acceptance.md#chief-of-staff-collaboration-scenarios) · [Workshop comparison workflow](https://github.com/microsoft/amplifier-persona-workshop/blob/df656e57d4870a51eab76d19bad8311c274bec86/README.md#build-a-profile) · [Workshop portable formats](https://github.com/microsoft/amplifier-persona-workshop/blob/df656e57d4870a51eab76d19bad8311c274bec86/docs/portable-exports.md) · [Instance import and restore](https://github.com/microsoft/amplifier-constellation-instance/blob/693cf06d9d0322efa6a5626cff24cbba517eb9fc/docs/api.md#portable-persona-profiles)

**Acceptance.** Check the new profile revision and, if the installed Instance provides `profile-use`, verify delivery on a fresh Matrix turn by session. Repeat the same acceptance cases with the same engine settings. Compare a concrete behavior such as stating command output and exit status before a handoff. Verify permissions, routing, attachments, and outcome ownership. Restore the previous profile and repeat one check. Profile delivery and behavior are two distinct observations. [Profile-use evidence](https://github.com/microsoft/amplifier-constellation-instance/blob/693cf06d9d0322efa6a5626cff24cbba517eb9fc/docs/responsibilities.md#profile-delivery-observations)

### 4. Evaluate Observatory as an optional fleet view

Connect the single existing Instance through private HTTPS. Pin its independently verified identity and use only the `observe` management scope on both sides of the integration. Use a pilot installation with no imported experiment transcripts. Keep ACP interaction, configuration, provisioning, and work reports outside the pilot. Observatory can add timestamped identity, readiness, and activity observations alongside the VPS resource dashboard. [Observatory existing-agent setup](https://github.com/microsoft/amplifier-constellation-observatory/blob/d366d9bf824f67625fa6b7f60cbb9dacea963421/README.md#connect-an-existing-agent) · [Observatory scopes](https://github.com/microsoft/amplifier-constellation-observatory/blob/d366d9bf824f67625fa6b7f60cbb9dacea963421/docs/api.md) · [Instance scopes](https://github.com/microsoft/amplifier-constellation-instance/blob/693cf06d9d0322efa6a5626cff24cbba517eb9fc/docs/api.md)

**Acceptance.** Show the correct live identity and a timestamped unavailable state when reachability is lost. Confirm that the observation credential cannot start a prompt, read full work reports, or change configuration. Verify that the normal Matrix path works independently of Observatory.

### 5. Compare background execution with the current Chief of Staff review path

Keep the current operator review path and evaluate a host timer if a recurring review cadence is needed. Instance's optional `agent-instance.scheduler/1` queues explicitly authorized work for one installed agent, with budgets, `work:execute` authority, and backend configuration approval. A responsibility due date is metadata. An interrupted prompt with uncertain effects requires reconciliation. A returned report enters review as an unverified claim and needs a separately authorized Matrix delivery action. Trial it only for a bounded, read-only task on a compatible Instance. [Background execution and recovery](https://github.com/microsoft/amplifier-constellation-instance/blob/693cf06d9d0322efa6a5626cff24cbba517eb9fc/docs/background-work.md) · [Responsibility ledger](https://github.com/microsoft/amplifier-constellation-instance/blob/693cf06d9d0322efa6a5626cff24cbba517eb9fc/docs/responsibilities.md)

**Acceptance.** Observe the authorized queue entry, actual start, report and review as distinct states. Interrupt a test run and verify the recovery record prevents automatic replay. If comparing Matrix delivery, prove that one authorized encrypted message returns to its originating request.

### 6. Apply the Connection contract before adding another conversation surface

Treat the existing Matrix bridge as the Connection. Use stable source/request IDs, scoped audience, attributed messages, and idempotent delivery receipts as its integration requirements. The Microsoft family index lists Slack, Teams and Minecraft connections. Conversations offers its own source-owned rooms and Huddles, where coordination can stay visible on demand and findings return to the originating request. A separate Huddle or external context-provider pilot is useful if the four Matrix scenarios expose a specific recurring gap in coordination or context retrieval. Keep any such trial isolated, with one synthetic room and an explicit contract for provenance, revocation, and outcome delivery. [Microsoft family index](https://github.com/microsoft/amplifier-constellation/blob/3935c23acc980b14a21231acd80726ef25a5a44c/family.toml) · [Connection contract](https://github.com/microsoft/amplifier-constellation/blob/3935c23acc980b14a21231acd80726ef25a5a44c/contracts/connection.md) · [Conversation grants](https://github.com/microsoft/amplifier-constellation-instance/blob/693cf06d9d0322efa6a5626cff24cbba517eb9fc/docs/conversation-continuity.md) · [Huddles](https://github.com/microsoft/amplifier-constellation-conversations/blob/976f2a705943cb4e79c320eb58dc5fd19ebaa030/docs/huddles.md)

**Acceptance.** Preserve Matrix attribution, thread identity, audience, and one terminal outcome. Exercise membership revocation, blocked work, attachment boundaries, and a retry after loss of acknowledgment before extending a trial. A positive pilot needs a measurable improvement over the existing Matrix route.
