# Communication policies

| Policy | Rule | Implementation and checks |
| --- | --- | --- |
| Assignment | The operator, Dot, or an authorized handoff can activate one registered Office agent with a real Matrix mention in new text. | [Matrix routing](../agents/connector/matrix-routing.mjs) · [Mention tests](../agents/tests/pilot.mjs) |
| Setup reminder | During interactive enrollment, the monitor sends one encrypted notice in Office once the operator's Element device has encryption keys. The notice directs the operator to finish registration in the terminal. It carries no mentions, and the monitor leaves Office after delivery. | [Monitor](../deploy/matrix/bot/monitor.mjs) · [Matrix smoke](../tests/operations-fixture.mjs) |
| Welcome | After setup and agent activation, Hiring Manager (or Chief of Staff on a legacy installation) sends one encrypted welcome in its private chat when selected. Otherwise, a ready Office agent posts it in Office. The welcome links to the verified workspace shortcuts in VPS Alerts. The examples show the operator how to start with Task Manager or another available Office agent through Element’s mention picker or the optional Dot plugin. The welcome carries no Matrix mentions. A retry reuses the original event. | [Onboarding](../deploy/onboarding.py) · [Matrix smoke](../tests/operations-fixture.mjs) · [First-task examples](../docs/setup-guide.md#-receive-the-welcome-and-send-a-task) |
| Handoffs | Keep work in the original thread. Match the recipient’s registered capability and resource scope. Limit a task to 15 agent replies and reserve the final managed reply for Task Manager. Direct status answers, polls, and retries are outside the reply budget. | [Managed task rules](../agents/connector/managed-task.mjs) · [Capability routing tests](../agents/tests/capability-routing.mjs) |
| Task outcomes | Each Office assignment has its own task ID, even in an existing thread. Record the handoff sender, recipient, acceptance, and returned result. Task Manager closes managed work. The initial assignee closes standalone work. A successful close cites verified Office evidence. Subtasks and status replies leave the overall outcome open. | [Office evidence](../agents/connector/context.mjs) · [Neo4j projection](../integrations/context-execution/engine/execution_timeline.py) · [Isolated graph test](../integrations/context-execution/tests/isolated) |
| Reactions | Add 👀 when an agent accepts an assignment and clear it after delivery. Mark the original request once with ✅ for verified success or ❌ for a terminal blocker. | [Office policy](../agents/connector/office-policy.mjs) · [Connector and durability](../agents/connector/connector.mjs) · [Delivery tests](../agents/tests/instance-acp.mjs) |
| Attachments | Check the room, authorized sender, file integrity, and the VPS’s 60 MB upload limit. Pass approved file references within the thread. | [Encrypted media](../agents/connector/matrix-media.mjs) · [Workspace tests](../agents/tests/workspace-mcp.mjs) |
| Approval polls | VPS Manager reports requests in the operator’s encrypted **Agents → Rooms → Root Operations** room. Each host action requires an operator vote tied to its exact proposal. Return a sanitized receipt to the source Office thread. Telegram Bridge shows the verified recipient and exact text, mentions the operator, and follows the preview with a native ✅ Accept / ❌ Decline poll. The first valid operator vote closes the poll. Accept rechecks the destination and publishes once. | [VPS Manager protocol](../integrations/root/protocol.mjs) · [Approval tests](../integrations/root/tests/run) · [Telegram policy](../integrations/telegram/policy.mjs) · [Telegram tests](../integrations/telegram/policy.test.mjs) |
| Office roster | Hiring Manager proposes hires and retirements privately. The host checks the exact encrypted operator vote. Only the operator can retire Hiring Manager. Accepted work drains before revocation. | [Approval flow](../integrations/chief-of-staff/direct/roster-approval.mjs) · [Host broker](../deploy/roster_broker.py) · [Lifecycle tests](../tests/test_roster.py) |
| Recurring staffing gaps | Group explicitly reported Office role gaps by uncovered duty. Require distinct assignments and cite their evidence in the private proposal. Recognize existing ownership, keep tool and credential blockers with Scouter, and deduplicate overlapping exact and semantic reviews. | [Grouping](../integrations/chief-of-staff/direct/staffing-clusters.mjs) · [Grouping tests](../integrations/chief-of-staff/direct/staffing-clusters.test.mjs) · [Matrix approval test](../tests/team-desks-fixture.mjs) |
| Contact permissions | New handoffs require an allowed outbound contact and a matching capability and resource. A verified return can travel back to its assigner. | [Contact policy](../agents/connector/agent-catalog.mjs) · [Assignment ancestry](../agents/connector/managed-task.mjs) · [Tests](../agents/tests/capability-routing.mjs) |
| Contact history | The current roster governs dispatch. Record committed topology changes with their actor and available evidence. Record returns against the originating handoff and distinguish them from dispatches. | [Registry history](../deploy/matrix/connection_history.py) · [Dashboard guide](../docs/team.md#team-connections) · [Retry tests](../tests/test_connection_history.py) |
| Coaching and tools | Coach applies evidence-backed working-style and ordinary contact revisions through Workshop. Changes involving VPS Manager contacts need approval. Scouter proposes a target-specific tool grant. The target must verify it before it becomes available. | [Private desks](../integrations/chief-of-staff/direct/team.mjs) · [Host changes](../deploy/team_management.py) · [Team checks](../tests/test_starter_team.py) |
| Dot visibility | A stable task ID makes publication idempotent. Dot reads only tasks it opened and may request a Telegram draft or update. | [Dot bridge](../agents/connector/dot-bridge.mjs) · [Telegram tool tests](../integrations/telegram/policy.test.mjs) |
| Telegram from Office | The operator can mention Task Manager to open or unlink a Telegram room and request a draft for a verified binding. The connector accepts these actions only from the operator. The encrypted Control room holds the draft and the operator’s approval. | [Office connector](../agents/connector/telegram-office.mjs) · [Private Telegram actions](../deploy/matrix/bot/telegram-office.mjs) · [Isolated Matrix test](../integrations/telegram/tests/bridge-smoke) |
| Telegram access | Telegram Bridge contains setup, `!tg` commands, recipient selection, drafts, and approval polls. Only the operator, bridge bot, and Telegram Agent join. Authentication commands stay outside agent requests. Telegram Agent joins verified linked chats through scoped provisioning. Each binding enables access to one chat, and unlinking revokes it. | [Provisioning](../integrations/telegram/bridge/office-portal.patch) · [Telegram smoke](../integrations/telegram/tests/bridge-smoke) |
| Helper | The operator asks plain-language questions in Helper’s encrypted DM. Only Task Manager can initiate a verified Office handoff to Helper. Helper reads deployed guides and sanitized health snapshots and returns the Office answer in its original thread. | [Contact enforcement](../agents/connector/agent-catalog.mjs) · [Private chat](../agents/connector/helper-dm.mjs) · [Helper tests](../tests/helper.test.mjs) |
| Telegram delegation | The operator can address Telegram Agent directly in Office or privately in Telegram Bridge. Task Manager can pass an operator request through the scoped Telegram connector. An MCP grant expires after that request’s tool turn. Ambiguous matches, drafts, and updates stay in Telegram Bridge. Office receives status and a private link. Dot uses a scoped local request socket. A direct Office assignment gets the standard activity and outcome reactions. | [Request broker](../integrations/telegram/delegation.mjs) · [Delegation tests](../tests/telegram-delegation.test.mjs) |
| Telegram room opening | Telegram Bridge resolves an exact person or known group, then offers a command to open the chat. A verified bridged chat belongs under Telegram Rooms. Layout repair updates the operator’s sidebar classification only for portals already linked in that Space. | [Bridge commands](../integrations/telegram/bridge/chat-link.patch) · [Room classification](../integrations/telegram/telegram_provision.py) · [Synapse test](../tests/layout_check.py) |
| Operations shortcuts | The monitor posts one encrypted pin containing the dashboard and Context Intelligence links in VPS Alerts after an operator device registers its encryption keys. It refreshes the managed pin when the device set changes and preserves operator-created pins. | [Pin reconciliation](../deploy/matrix/bot/pins.mjs) · [Pin tests](../tests/dashboard.test.mjs) |
| Workspace | General Office workers can read and write the shared desktop. Use task-specific paths, coordinate simultaneous edits in Office, and keep credentials in private state. | [Workspace tool](../agents/connector/workspace-mcp.mjs) · [Workspace tests](../agents/tests/workspace-mcp.mjs) |
